Bit 5 can never be set

ODY_ARMBLOCK_CALIB — “calibration did not pass” — is defined in the wire protocol and raised by no code anywhere. Every other blocker has exactly one call site; this one has zero.

It is unreachable by construction rather than by oversight: blockers are only evaluated from PREFLIGHT_OK, which is the state you are in because calibration passed. But the ground station decodes this byte and will never see bit 5, so the protocol advertises a reason it cannot report. Harmless today; a trap for anyone who writes a decoder from the header.

Required, versus merely watched 6 of 13 sensors

Thirteen sensor flags exist. Only six gate arming — so seven can be dead and the aircraft will still take off. That is mostly deliberate, and worth knowing exactly.

You can arm without the rangefinder that lands the aircraft

ODY_SENS_TOF_DOWN is not in the required set, but §8 gives the VL53L1X the landing flare and the touchdown veto. The same is true of the forward LiDAR, the backup IMU, the SD card, the LoRa link and the AUX bus.

Most of those are right: a dead SD card should not ground an aircraft, and refusing to fly without telemetry would be worse than flying without it. The downward ToF is the one worth a deliberate decision rather than an inherited default — it degrades to a barometric landing, which works, but nobody has written down that this was chosen.
